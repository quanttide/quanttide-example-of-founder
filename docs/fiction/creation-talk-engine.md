# 创作谈引擎（Creation-Talk Engine）

> 定位：从创作日志提炼创作谈的通用程序规格。规则可变，提炼规则的程序不变。
> 本篇为实现规格。实现前，先读关联篇目（fiction-revision.md、fiction-adaptation.md）——它们是本引擎预期产出的两个实例。

## 1. 要解决的问题

创作方法论的现状：靠人在某个时刻坐下来，手工对比 diff、归纳规律、写成文档（fiction-revision.md 与 fiction-adaptation.md 都是这样诞生的）。三个瓶颈：

1. **依赖心情与精力**——不坐下来归纳，经验就散在日志里
2. **不可复用**——每类文本（精修/改编/场景/初稿）都要手工重来一遍
3. **不可持续**——方法论写成即冻结，后续日志里的新证据无法回流

目标：把"从创作日志提炼创作谈"变成一台**随时可跑的标准程序**。输入任意创作日志，输出该类文本的规则集（创作谈）。规则集是产物、是文件，不是代码的一部分。

## 2. 与现有体系的关系

```
创作日志（journal / 各阶段文件夹）          ← 探路者的原始记录
      ↓ 【创作谈引擎】（本规格要实现的程序）
创作谈（docs/fiction/*.md 规则集文件）      ← 可复制的方法论资产
      ↓ 【评估器】（现有 revision 功能，读规则文件工作）
文本处理建议（逐条：原文 → 建议 + 理由）    ← 终审归作者
      ↓ 作者采纳/拒绝/改写
新的创作日志（下一轮 diff）                 ← 喂回引擎，规则换代
```

- 本引擎 = 提炼端；现有 revision = 应用端。两者以**规则集文件**解耦
- 对应学习管理体系：创作日志 = journal，创作谈 = schedule，评估器建议 = follower 的作业反馈

## 3. 输入规格

引擎每次运行接受两个输入：

### 3.1 素材：创作日志

有效素材按证据强度分三档：

| 档 | 形态 | 证据强度 | 说明 |
|----|------|---------|------|
| A | 成对文本（改前/改后 diff） | 强 | 每处改动直接构成一条规则证据。来源：`1_日志→5_定稿` 各阶段文件夹的同名对照、git 历史 |
| B | 过程日志（含决策叙述） | 中 | 作者写了"为什么这么改/不这么改"的日志条目。来源：各部小说 `1_日志/创作日志N.md`、memory/journal |
| C | 纯结果文本 | 弱 | 只有成品没有过程。只能归纳风格特征，提炼出的规则标"弱证据" |

一次提炼可混合多档素材，但产物中每条规则须标注所依据的最高档证据。

### 3.2 目标说明（提炼任务参数）

- **目标文本类型**：提炼出的规则将来约束什么（前言/场景/初稿/整章……）
- **规则视角**：要的是"修改原则"（如精修七条）还是"转化规律"（如改编八条）还是"风格特征"
- **输出格式**：规则集文档（默认）/ 创作谈（面向读者的叙事形态）

## 4. 输出规格：规则集文件

产物是 Markdown 文件，落 `docs/fiction/`（或其他主题目录），格式对齐既有两篇创作谈的结构：

```markdown
# {规则集标题}

> 基于何时何素材的归纳。标注【N 次】为证据命中次数。

## 规则 N：{一句话原则}

- 证据：{来源日志位置 + 原始片段}
- 命中：【N 次】
- {操作级说明：什么情况适用、执行时注意什么}

## 应用方式
## 本质归纳（删掉/留下的是什么——交换的表述）
```

硬性要求：

1. **每条规则必须附证据链**：来源位置 + 原始片段。无证据的规则不输出（宁可少，不可编）
2. **证据强度标注**：A/B/C 档如实标注
3. **倾向性声明**：默认携带"这些是倾向性准则，不是硬规则；作者保留判断权"
4. **文件头带素材清单**：本次提炼读了哪些文件，可复现

## 5. 程序形态

- CLI：`lab creation-talk <素材路径...> --goal "<目标说明>"`，产物打到 stdout 或 `--output` 指定文件
- 与 revision 同架构：领域逻辑进 `laboratory_core`（`src/creation_talk.rs`），CLI 是薄壳
- SYSTEM_PROMPT 只装**提炼任务本身的规则**（怎么从素材归纳规则、怎么标证据、怎么定粒度），**不装任何具体创作规则**——具体规则全部来自输入素材，这是"规则可变、程序不变"的实现要点

## 6. 提炼质量约束（程序的行为准则）

1. **证据链强制**：输出前自检每条规则是否可指回素材原文；指不回的删除
2. **保守输出**：素材不足时如实输出"证据不足以提炼规则"，不强造条目
3. **粒度对齐**：规则粒度对齐既有创作谈（一条规则 = 一个可执行的操作原则 + 例证），过泛（"要多改几遍"）或过细（只适用一次的偶发操作）都不输出
4. **冲突保留**：素材中互相矛盾的实践（如一次保留公司维度、一次删除）如实记为"作者权衡项"，不强行统一——作者保留判断权是体系前提

## 7. 验收标准

以既有两篇创作谈为验收基准：

1. 把 fiction-revision.md 的原始素材（两轮精修 diff）喂给引擎，产出应覆盖现有七条原则中的至少五条（粒度与表述允许不同）
2. 把 fiction-adaptation.md 的原始素材（脚本/成稿对照）喂入，产出应覆盖八条转化规律中的至少五条
3. 产出的每条规则都能在素材中指认出原文证据
4. 用一份引擎没见过的日志（如重生言情的 1_日志）跑通完整流程，产物结构完整、证据可指认

## 8. 实现排期

1. 规格评审（本篇目确认）
2. `src/creation_talk.rs`：最小实现（A 档 diff 素材 → 规则集）
3. 验收标准 1/2 跑通（用历史素材回归验证）
4. B/C 档素材支持
5. 创作谈叙事形态输出
