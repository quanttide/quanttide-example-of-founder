# 创作谈引擎

创作日志 → 程序 → 创作谈。

规则可变，提炼规则的程序不变。

## 什么是创作谈

创作谈是**一篇完整的文章**，不是分析报告。读者读它像读一篇随笔：有叙述、有转折、有具体的事。方法论藏在叙述里，不列条目、不贴标签。

范本：作者写的三篇创作谈（quanttide-founder/assets/fiction 的 `创作谈/` 目录）——半自传体小说、2026 年开篇、AI 小说阅读体验。它们是这篇文章体的事实标准。

## 用法

```
lab creation-talk <日志文件...>
```

输入：一个或多个创作日志（作者的写作过程记录）。

输出：一篇可以直接发表的创作谈（Markdown）。

## 引擎的工作方式

SYSTEM_PROMPT 只写写作方法，不写任何具体创作规则：

1. 通读素材，找出里面真实的瞬间：顿悟、转折、自我说服、踩坑、告别——这些瞬间是文章的骨骼
2. 以作者的第一人称写，"我渐渐发现"是基本语气；方法论从瞬间里自然显影，不单独列条目
3. 日志原话尽量保留——那是最真实的声音，融入句子而非改成书面腔
4. 素材里没有可讲的事就一句话如实说，不分析原因
5. 写完自检：拿掉所有结构标记后，这篇文章还像一篇随笔吗？不成立就重写

## 验收

1. 读起来像一篇作者写的随笔，不像 AI 的分析报告（对照：作者的三篇创作谈）
2. 文中的每个具体做法都能在日志里找到出处
