# p09 实验室目录 — 实验方案

## 实验目的

验证用统一的目录索引管理多个实验室仓库是否可行，能否解决"东西太多整理费劲"的问题。

## 背景

日志 2026-06-01："实验室里面产生的东西太多了，然后整理起来会很费劲"、"以仓库为单位直接进行丢弃"。

## 实验假设

1. 一个轻量目录页面能清晰展示所有实验室的状态和内容
2. 按领域分组 + 标签过滤比单纯列表更好用
3. 目录本身也是一个实验室仓库的一部分，通过 CI 自动更新

## 实验设计

### 数据模型

```
Lab {
  name: string
  repo: string
  domain: 'human' | 'org' | 'exec' | 'company' | 'innov' | 'game' | 'default' | 'devops'
  status: 'active' | 'archived' | 'deprecated'
  pocCount: number
  lastUpdated: date
  description: string
  pocList: Poc[]
}
```

### 场景 1：目录渲染

将所有实验室数据写为一个 JSON，渲染为可浏览的目录页面：

| 领域 | 实验室 | 状态 | PoC 数 | 最后更新 |
|------|--------|------|--------|---------|
| 人力资源 | human | active | 1 | ... |
| 组织管理 | org | active | 1 | ... |
| 执行管理 | execute | active | 2 | ... |
| ... | ... | ... | ... | ... |

### 场景 2：过滤与搜索

- 按领域筛选
- 按状态筛选（active/archived）
- 关键词搜索

### 场景 3：状态标记

实验"以仓库为单位直接进行丢弃"的逻辑：

- 标记仓库为 `deprecated`
- 目录页面自动隐藏（可通过参数显示）
- README 中生成归档说明

## 评价标准

| 指标 | 合格线 | 优秀线 |
|------|--------|--------|
| 目录覆盖 | 5 个实验室 | 所有仓库 |
| 筛选响应 | < 500ms | < 200ms |
| 状态管理 | 手动更新 JSON | CI 自动抓取 |

## 原型实现

单 HTML 文件（零依赖），包含：

- 实验室卡片网格（按领域分组）
- 筛选栏（领域 / 状态 / 搜索）
- 每个卡片：名称、领域、状态、PoC 数、描述、链接
- 数据以内嵌 JSON 方式存储

## 下一步

目录跑通后，加入 CI 自动更新（监听各仓库的 release/webhook），目录数据自动同步。
