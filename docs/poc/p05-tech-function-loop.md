# p05 技术职能协作循环

## 来源

日志 2026-05-28：技术写骨架 + 职能线填业务逻辑，故意留坑观察开发者判断力。

## 验证目标

技术线写骨架代码 + 职能线填充业务逻辑的协作模式能否闭环。

## 验收标准

1. 骨架代码规范定义（接口/契约/扩展点）
2. 状态命令设计样例（故意留坑）
3. 埋坑记录可追溯
4. 观察报告：开发者遇到问题的决策路径
5. 协作循环指标：首次交付时间、缺陷率

## 关键问题

- 骨架的粒度多细合适？
- 埋坑策略：技术坑 vs 业务坑？
- 如何区分"遇到问题提问"和"根本没发现坑"？

## 协作模型

```
Tech Team:
  - 定义接口契约 (interface/abstract class)
  - 实现基础设施（存储/权限/通知）
  - 故意留坑（边界条件/异常处理）

Function Team:
  - 填充业务逻辑（状态命令/规则引擎）
  - 发现坑 → 提问 / 自主修复
  - 交付功能

Observation:
  - 记录决策路径
  - 统计处理方式
  - 调整协作策略
```
