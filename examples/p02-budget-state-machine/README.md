# p02 财务预算状态机 — 实验方案

## 实验目的

验证预算模块核心状态流转设计是否覆盖主要业务场景，状态机是否可执行。

## 背景

日志 2026-05-28：正式进入业务研发的财务预算模块，作为核心业务功能之一。

## 实验假设

1. 标准状态流转（编制→审批→执行→决算）能覆盖 80% 以上的日常预算场景
2. 状态机形式化描述后，非技术角色也能理解和验证
3. 异常路径（超支、退回、调整）的处理逻辑可提前发现设计漏洞

## 实验设计

### 阶段 1：正常路径验证

准备 5 个预算场景，逐一执行标准流转：

| 场景 | 预算类型 | 金额 | 预期路径 |
|------|---------|------|---------|
| 招聘费用 | 运营 | 5 万 | 编制→审批→执行→决算 |
| 服务器采购 | IT | 20 万 | 编制→审批→执行→决算 |
| 咨询项目 | 项目 | 50 万 | 编制→审批→执行→决算 |
| 日常办公 | 运营 | 1 万 | 编制→审批→执行→决算 |
| 年度培训 | 项目 | 30 万 | 编制→审批→执行→决算 |

### 阶段 2：异常路径验证

模拟以下异常情况：

- 超支告警：执行中超预算 120%
- 审批退回：审批人拒绝，退回草稿
- 预算调整：执行中申请追加
- 预算调剂：A 项目剩余额度转 B 项目

### 阶段 3：多版本验证

- 草稿与正式版并行
- 调整后生成新版本
- 历史版本可追溯

## 评价标准

| 指标 | 合格线 | 优秀线 |
|------|--------|--------|
| 标准路径覆盖 | 5/5 | 5/5 |
| 异常路径处理 | 3/4 | 4/4 |
| 状态图与实际代码一致 | 是 | 是 |
| 非技术角色理解状态图 | 60% | 80% |

## 原型实现

状态机可视化面板，包含：

- 状态图渲染 + 高亮当前状态
- 事件触发按钮（提交/审批/驳回/执行/决算）
- 预算额度实时显示
- 超支告警弹窗
